02 / 06
Progress

1. Overall Progress

The core loop around “Event → TTT → Execution → RoundReview → TTT” is now connected end to end, and repeated validation has begun on open datasets.

Completed so far

  • Established a three-role collaboration framework for coordinated traceback analysis.
  • Designed a three-tier Traceback Task Tree (TTT) to serve as the core working memory.
  • Integrated a long-term memory layer for reusable knowledge and prior context.
  • Validated the end-to-end pipeline through single-alert investigation runs.

Current tuning focus

  • Further strengthen the long-term memory layer for more effective context reuse and knowledge accumulation.
  • Extend the system to integrate and adapt to a broader set of investigation tools.
  • Conduct more systematic evaluation on the BOTS open dataset across diverse alert scenarios.
With the core workflow now in place, the next stage is to strengthen long-term memory, broaden tool integration, and carry out more systematic validation on the BOTS dataset.

Integrated Tools and Data Sources

  • Splunk serves as the primary investigation backend, and we have wrapped an SPL query tool for log search, entity pivoting, timeline reconstruction, and evidence collection on BOTS data.
  • VirusTotal provides IP threat reputation, detection summaries, and external intelligence pivoting for suspicious indicators.
  • IPInfo adds ASN ownership, geolocation, network attribution, and related domain context for infrastructure enrichment.
  • ...and this capability surface will continue to expand as new tools and data sources are explored, adapted, and integrated.

Long-Term Memory

  • Semantic Knowledge: stores broad security knowledge, currently at roughly 1.2 GB scale.
  • Procedural Knowledge: stores traceback workflows. Based on collected BOTS traceback references and LLM summarization, we currently maintain about 20 event-specific workflow categories under active testing and revision.
  • Factual Knowledge: stores background context and environment facts. At the current stage, this mainly includes supporting background information for the BOTS dataset.

Dataset

3. BOTS Dataset

BOTS (Boss of the SOC) is an open security-analysis dataset provided by Splunk. It is well suited for attack traceback, log correlation analysis, and query-strategy validation.

Why we use it

  • The data is public, which makes experiments reproducible and easy to present.
  • It includes host, network, and perimeter-device logs.
  • It is suitable for simulating evidence-chain assembly in real SOC investigations.
  • It helps validate whether the multi-round workflow generalizes.

How we use it now

  • botsv1 is the default dataset, with botsv2 and botsv3 reserved as well.
  • Queries run through the Splunk REST API rather than an offline mock.
  • The main goal is to verify whether TTT task decomposition maps well to real log queries.
  • We keep checking whether summaries, sample events, and review outputs are reasonable.

Typical log types

  • Windows / Sysmon
  • IIS / Stream / DNS / HTTP
  • Suricata / FortiGate
  • Registry and host-behavior logs

Why it matters at this stage

  • It grounds the multi-agent workflow in a real log-investigation setting.
  • It makes it easier to compare different query strategies and task-tree designs.
  • It provides a unified validation baseline for future security-tool integrations.

Stack

4. Frontend and Backend Stack

The current implementation favors a lightweight, runnable setup that is easy to iterate on, prioritizing real and testable workflows over early deployment complexity.

Backend

  • Python 3.13
  • Flask + Flask-SocketIO
  • SQLite as the shared state hub
  • OpenAI-compatible LLM integration
  • Splunk, VirusTotal, and IPInfo tool integration

Frontend

  • Jinja2 template pages
  • Bootstrap 5
  • Vanilla JavaScript
  • Socket.IO real-time message updates
  • Home page + War Room two-page structure

Next Steps

5. Next Steps

The next phase focuses on improving investigation quality, broadening runtime capability, and turning the current prototype into a more stable experimentation platform.

Priority Directions

  • Deepen the long-term memory layer so prior context and accumulated knowledge can play a stronger role in future traceback rounds.
  • Expand the investigation capability surface by connecting more tools and improving how the agents adapt to each external interface.
  • Carry out broader and more systematic experiments on the BOTS open dataset to assess performance under varied alert conditions.
